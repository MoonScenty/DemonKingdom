# 1. 게임 콘셉트

플레이어는 어느 날 갑자기 마왕으로 임명된다.

그러나 물려받은 마왕국은 거대한 제국이 아니라 다음과 같은 상태다.

* 마왕성 대부분이 무너져 있음
* 금고에 금화가 거의 없음
* 주민들이 일을 제대로 하지 않음
* 생산 시설이 모두 고장 나 있음
* 인간 모험가들이 수시로 침입함
* 마족 간부들이 서로 책임을 떠넘김
* 주변 마왕국은 플레이어의 영토를 노리고 있음

플레이어는 폐허에 건물을 세우고, 주민에게 직업을 배정하고, 생산 체인을 연결하며 마왕국을 재건한다.

게임의 핵심은 완벽한 도시를 만드는 것이 아니다.

**문제를 일으키는 주민들과 사고가 끊이지 않는 도시를 어떻게든 성장시키는 것**이 핵심이다.

# 2. 핵심 재미

## 2.1 눈에 보이는 빠른 성장

플레이 시작 직후부터 도시가 빠르게 변화해야 한다.

* 폐허가 제거된다.
* 새로운 길이 생긴다.
* 건물이 완성된다.
* 주민이 도시로 이주한다.
* 생산품이 건물 사이를 이동한다.
* 마왕성이 단계적으로 복구된다.
* 안개가 걷히며 새로운 구역이 열린다.

단순히 숫자만 증가하는 것이 아니라 도시 화면 자체가 계속 변해야 한다.

## 2.2 연속 보상

플레이어는 짧은 주기로 보상을 받는다.

* 생산 완료
* 퀘스트 완료
* 건물 레벨 상승
* 주민 레벨 상승
* 새로운 건물 발견
* 새로운 종족 영입
* 지역 확장
* 사건 해결
* 업적 달성

한 번의 행동이 다음 행동으로 자연스럽게 이어지도록 설계한다.

## 2.3 문제투성이 주민

주민은 생산량을 올려주는 단순한 카드가 아니다.

도시 안을 직접 돌아다니며 일하고, 쉬고, 식사하고, 서로 다투고, 사고를 일으킨다.

예시:

* 슬라임이 창고의 물약을 마심
* 고블린이 급여 인상을 요구함
* 오우거가 출입문이 작다며 건물을 부숨
* 리치가 묘지 주민을 멋대로 부활시킴
* 임프가 폭발물을 잘못 배송함
* 뱀파이어가 낮 근무를 거부함

이러한 사건은 손해만 주는 것이 아니라 새로운 콘텐츠와 보상으로 연결된다.

## 2.4 도시 자동화

초기에는 플레이어가 직접 자원을 회수하고 주민을 배치한다.

도시가 성장하면 자동화 시설이 열린다.

* 자동 수거 골렘
* 임프 운송대
* 마법 물류 포털
* 자동 생산 명령서
* 마나 철도
* 도시 관리 비서

초반에는 직접 조작하는 재미를 주고, 후반에는 도시를 설계하고 최적화하는 재미로 전환한다.

# 4. 도시 건설 시스템

## 4.1 도시 맵

도시는 타일 기반으로 구성한다.

초기 맵은 20×20 타일로 시작하며, 확장을 통해 주변 구역이 추가된다.

각 타일에는 다음 중 하나가 배치된다.

* 건물
* 길
* 장식물
* 자원 지형
* 장애물
* 랜드마크
* 방어 시설

## 4.2 건물 배치

건물은 마우스로 선택해 원하는 타일에 설치한다.

지원 기능:

* 배치 미리 보기
* 회전
* 이동
* 철거
* 일괄 이동
* 배치 취소
* 유효 타일 표시
* 건물 영향 범위 표시

건물 배치 중에는 설치 가능 영역은 밝게, 불가능한 영역은 붉게 표시한다.

## 4.3 건물 시너지

특정 건물을 가까이 배치하면 추가 효과가 발생한다.

| 조합           | 효과          |
| ------------ | ----------- |
| 농장 + 제빵소     | 식량 생산 증가    |
| 광산 + 대장간     | 장비 생산 속도 증가 |
| 마나 우물 + 연구소  | 연구 시간 감소    |
| 시장 + 창고      | 판매 가격 증가    |
| 주점 + 모험가 길드  | 방문객 증가      |
| 묘지 + 흑마법 연구소 | 언데드 생성      |
| 병영 + 감시탑     | 방어력 증가      |

시너지가 발생하면 건물 사이에 빛, 화살표, 운송 경로 등의 효과를 보여준다.

## 4.4 건물 등급

건물은 다음 단계로 성장한다.

1. 폐허
2. 임시 시설
3. 정식 시설
4. 전문 시설
5. 마왕국 핵심 시설
6. 전설 등급 시설

건물 등급이 오르면 다음 요소가 함께 변경된다.

* 외형
* 크기
* 애니메이션
* 생산품
* 생산 속도
* 배치 가능한 주민 수
* 특수 능력

## 4.5 랜드마크

각 도시 구역에는 대형 랜드마크를 하나씩 세울 수 있다.

* 마왕성
* 지옥문
* 거대 마나 수정
* 고대 용의 둥지
* 공중 요새
* 악마 소환탑
* 황금 슬라임 동상

랜드마크는 완성 과정이 도시 화면에 단계별로 표시된다.

## 기본 자원

* 금화
* 식량
* 목재
* 광석
* 마나

## 가공 자원

* 광석 → 철괴 → 무기
* 목재 → 목재 판자 → 가구
* 밀 → 밀가루 → 빵
* 마나 → 마법석 → 마법 장비
* 몬스터 가죽 → 가죽 → 방어구
* 영혼 조각 → 저주석 → 흑마법 도구

## 생산 방식

건물에는 다음 정보가 존재한다.

* 생산 품목

* 필요 주민
* 소비 자원
* 생산 보너스
* 인접 건물 효과

생산이 완료되면 건물 위에 자원 아이콘이 표시된다.

자동 수거가 해금되기 전에는 플레이어가 클릭해 수집한다.

# 6. 주민 시스템

## 기본 주민 종족

### 슬라임

* 유지비가 낮음
* 어떤 시설에도 배치 가능
* 생산 능력이 낮음
* 자주 쉬거나 엉뚱한 행동을 함

* 생산과 상업에 강함
* 급여와 불만 관리가 필요함

* 건설과 채광에 강함
* 이동 속도가 느림

* 고급 주거 시설을 요구함

### 리치

* 연구와 마법에 강함

# 7. 사건 시스템

도시는 일정 시간마다 작은 사건이나 대형 사건을 발생시킨다.

## 작은 사건

* 주민 다툼
* 생산 시설 고장
* 창고 도난
* 음식 부족
* 배송 실수
* 작은 화재

## 대형 사건

* 고블린 총파업
* 마법 연구소 폭발
* 인간 영웅 습격
* 드래곤의 금고 점거
* 언데드 대량 부활
* 주변 마왕의 선전포고

## 선택 예시

### 고블린들이 파업을 시작했습니다

1. 급여를 인상한다.
2. 무료 맥주를 제공한다.
3. 주동자를 감옥에 가둔다.
4. 마왕의 위엄으로 협박한다.

각 선택은 즉시 결과와 후속 결과를 함께 가진다.

예를 들어 무료 맥주를 제공하면 파업은 종료되지만 주점의 식량이 감소하고 다음 날 숙취 사건이 발생할 수 있다.

# 9. 오프라인 성장

플레이어가 접속하지 않은 동안에도 일부 생산이 진행된다.

오프라인 보상은 클라이언트 컴퓨터 시간이 아니라 서버 시간을 기준으로 계산한다.

## 기본 규칙

* 마지막 서버 저장 시각 기록
* 재접속 시 서버 현재 시각과 비교
* 생산 건물과 주민 상태를 기준으로 보상 계산
* 창고 최대 용량까지만 생산
* 초기 오프라인 생산 상한은 8시간
* 연구나 탐험은 남은 시간을 차감
* 사건은 무한 누적되지 않고 최대 개수 제한

재접속 시 결과를 한꺼번에 보여주는 것이 아니라 다음 순서로 연출한다.

1. 도시가 다시 활성화된다.
2. 주민들이 일제히 움직인다.
3. 생산 결과가 건물에서 솟아 나온다.
4. 금고와 창고로 자원이 이동한다.
5. 오프라인 보고서가 표시된다.

## 중요 설계 원칙

PixiJS 객체를 Pinia Store 안에 직접 저장하지 않는다.

Pinia에는 순수한 게임 데이터만 저장하고, PixiJS 렌더러가 Store 변화를 감지해 화면을 갱신한다.

예시:

```text
Pinia의 BuildingData
        ↓
BuildingRenderer가 감지
        ↓
PixiJS Sprite 생성 또는 갱신
```

이 구조를 사용하면 세이브 데이터와 화면 렌더링 객체가 뒤섞이지 않는다.

따라서 게임 상태 전체를 JSON으로 저장하고, 검색이나 랭킹에 필요한 핵심 정보만 별도 컬럼으로 보관한다.

## 12.4 자동 저장

다음 상황에서 자동 저장한다.

* 게임 시작 후 초기 월드 생성
* 데이터 변경 후 10초 동안 추가 변경이 없을 때
* 마지막 저장 후 60초가 지났을 때
* 건물 건설 완료
* 지역 해금
* 희귀 주민 획득
* 사건 선택 완료
* 탐험 출발 또는 귀환
* 시대 전환
* 브라우저 종료 시도

브라우저 종료 시 저장 요청은 실패할 수 있으므로 종료 저장에만 의존하지 않는다.

## 12.5 로컬 임시 저장

네트워크 장애에 대비해 IndexedDB에도 임시 저장한다.

```text
플레이어 행동
    ↓
Pinia 상태 변경
    ↓
IndexedDB 임시 저장
    ↓
Laravel 서버 저장 요청
    ↓
성공 시 서버 revision 갱신
```

서버 저장이 실패하면 상단에 다음 상태를 표시한다.

* 저장 중
* 저장 완료
* 오프라인 상태
* 저장 재시도 중
* 세이브 충돌 발생

## 12.6 세이브 충돌 방지

각 세이브에는 `revision` 값을 둔다.

예시:

1. 클라이언트가 revision 15를 불러온다.
2. 저장 요청에 기준 revision 15를 전달한다.
3. 서버 현재 revision이 15이면 저장한다.
4. 저장 후 revision을 16으로 증가시킨다.
5. 서버 revision이 이미 16이라면 409 Conflict를 반환한다.

충돌이 발생하면 다음 선택지를 제공한다.

* 서버 세이브 불러오기
* 현재 기기의 임시 세이브 확인
* 최신 세이브 비교
* 지원용 백업 생성

서버 저장 처리는 데이터베이스 트랜잭션과 행 잠금을 사용해 동시에 두 요청이 저장되는 것을 막는다.

## 12.7 데이터 버전 관리

게임 업데이트로 저장 구조가 변경될 수 있으므로 `schemaVersion`을 사용한다.

예시:

```text
schemaVersion 1
    ↓
SaveMigrationV1ToV2
    ↓
schemaVersion 2
    ↓
SaveMigrationV2ToV3
    ↓
schemaVersion 3
```

기존 사용자의 세이브를 삭제하지 않고 최신 구조로 변환한다.

* revision이 일치하는지
* 오프라인 시간이 비정상적으로 크지 않은지

랭킹이나 유료 재화가 추가되면 중요 행동을 서버 명령 방식으로 전환한다.

# 18. 첫 번째 플레이 가능 버전

첫 번째 플레이 가능 버전의 목표는 다음과 같다.

1. 사용자가 회원 가입 또는 게스트 시작을 한다.
2. 새로운 마왕국을 생성한다.
3. 폐허가 있는 20×20 도시가 표시된다.
4. 주택, 농장, 벌목장을 배치한다.
5. 슬라임과 고블린이 건물 사이를 이동한다.
6. 식량과 목재가 생산된다.
7. 건물을 업그레이드한다.
8. 간단한 주민 사고가 발생한다.
9. 서버에 자동 저장된다.
10. 브라우저를 닫고 다시 접속해도 도시가 복원된다.
11. 접속하지 않은 시간의 생산 결과가 표시된다.

이 단계에서 도시를 확장하는 행동 자체가 재미있고, 저장과 복원이 안정적으로 동작하는지를 먼저 검증한다.

# 19. 최종 개발 원칙

1. Vue는 인터페이스를 담당한다.
2. PixiJS는 도시 화면만 담당한다.
3. Pinia에는 직렬화 가능한 순수 데이터만 저장한다.
4. 게임 규칙은 Vue 컴포넌트나 PixiJS 객체에 직접 작성하지 않는다.
5. Laravel은 계정과 최종 세이브를 관리한다.
6. IndexedDB는 서버 장애 시 임시 저장 용도로 사용한다.
7. 모든 세이브에는 revision과 schemaVersion을 둔다.
8. 초반에는 재미 검증을 우선하고, 서버 검증은 단계적으로 강화한다.
9. 첫 번째 목표는 콘텐츠 양이 아니라 도시 건설과 성장의 손맛이다.
10. 브라우저를 닫았다 다시 열어도 안전하게 이어지는 경험을 최우선으로 한다.
